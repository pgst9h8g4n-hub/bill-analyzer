# 2026-10-03 账单导入功能（支付宝 CSV + 微信 xlsx）+ 方向/中性交易模型

## 需求来源
在首页-手动录入新增"导入账单"入口，导入支付宝/微信导出的消费账单，识别记录进入消费明细。记账口径升级为三分类：支出（记负）、收入（记正）、中性交易（转账/还款/理财，不入消费/收入汇总，明细灰色弱化）。抖音 PDF 留到下一步（PDF→图片→OCR）。

## 解析器（新建 `src/lib/parse/`）
- `category-keywords.ts`：从 OCR 页抽出的 `MERCHANT_CATEGORY`/`CATEGORY_ALIASES` 共享表 + `normalizeCategoryName`/`matchKeywordCategory`
- `types.ts`：`ParsedRecord` 中间形态 + `categoryForRecord`（中性→转账分类；收入/支出→归一化匹配，落不到→待整理）
- `alipay.ts`：GBK 解码 CSV，定位"交易时间"表头；收支 支出/收入/不计收支 + 投资理财(余额宝收益)→neutral fund_return；退款状态→refund
- `wechat.ts`：SheetJS 读 xlsx（A 列 Excel 序列→本地日期）；收/支 支出/收入/中性交易 + 交易类型判 转账/还款/理财/红包；"已退款"→refund
- `index.ts`：`detectSource`（文件名含"支付宝"/.csv→alipay，含"微信"/.xlsx→wechat）+ `parseBillFile`

## 抖音 PDF 导入（同日续做）
- 用户确认记账口径：理财/基金收益、退款 → 记**收入（正数）**；转账卡/还款 → 中性（不入消费/收入）。已落到上面三个解析器的方向判定里。
- 抖音 PDF 实测发现是**带文本层**的 PDF（/Font /Type0 CJK + Tj/TJ + FlateDecode），数字（时间/金额/单号）直接可读，CJK 标签需字体 cmap 才能解。故改用 **pdfjs-dist 文本抽取**（比原计划的"栅格化→OCR"更可靠、更省），而非复用 Tesseract OCR。
- 数据布局（文本层按 y 分行、x 排序）：
  - 表头区：编号/导出时间/支付交易流水/交易时间段/交易类型（含日期的说明行、列头行需跳过）
  - 列锚点：交易时间 x≈31 / 收·支 x≈145 / 金额 x≈212 / 收付款方式 x≈276 / 交易单号 x≈370 / 交易对方 x≈575 / 商家单号 x≈713
  - 记录以"交易时间列含日期"为锚点切块；长值换行续片（如 `中信银行信用卡（6` → 下一行 `963）`、商家单号尾段）按 x 距离 ≤8pt 并入同列
- 新建 `src/lib/parse/douyin.ts`：pdfjs `legacy` build（标准 build 在 Node 报 hashOriginal 错，浏览器下正常但统一走 legacy 一致）→ `getDocument` → 每页 `getTextContent` → 按 y/x 分组 → 日期锚点切块 → 列锚点取值 → 方向判定（退款/理财→income；信用卡/花呗还款→neutral repay；其余消费/抖音月付/银行支付→expense consumption）
- `src/lib/parse/index.ts`：`detectSource` 加 `.pdf`/"抖音"/`dy_` 前缀 → `douyin`；`parseBillFile` 分发到 `parseDouyinPdf`
- `src/lib/parse/types.ts`：`ParsedRecord.source` 加 `'douyin'`
- `src/routes/import/+page.svelte`：文件 accept 加 `.pdf`，提示文案加"抖音 .pdf"，`source` 类型加 `douyin`
- `src/routes/+page.svelte`：导入账单卡副标题 "支付宝/微信" → "支付宝/微信/抖音"
- `package.json`：`npm i pdfjs-dist`（6.3.289，worker 走 Vite 资源 `pdf.worker.min.*.mjs`）

## 退款逻辑修正（同日）
用户提出：退款应冲减消费合计而非计入收入，否则消费统计失真。调整如下：
- 三个解析器（`alipay.ts`/`wechat.ts`/`douyin.ts`）：退款方向从 `income` 改为 `neutral`（subType 仍 `refund`），与"理财收益"区分。
- `expense-math.ts`：新增 `isRefund(e)`（subType==='refund' 或 is_refund===true）。
- `expenses/+page.svelte`：顶部汇总新增"退款合计（已冲减消费净额）"琥珀色行；退款行标签/金额均改为琥珀色；`summary` 返回结构含 `refund` 字段。
- `import/+page.svelte`：预览列表退款行显示"退款"标签 + 琥珀色金额，不再显示为绿色收入。
- `export.ts`：CSV 导出方向列退款显示"退款"而非"中性"。
- 消费净额口径不变：`expenseSigned` 已对 neutral+refund 返回 +amount（冲抵），`isConsumptionScope` 含 refund，故消费净额 = 所有消费 − 退款合计。
